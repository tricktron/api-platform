01 — Pre-Render Structural Templates

Execute Go text/template on raw YAML bytes before parsing, enabling template expressions to produce non-scalar YAML values (arrays, objects).

User Story

As a platform team deploying APIs in immutable mode, I want template expressions in artifact YAML files to produce arrays and objects so that I can share a single API definition across environments where only env-var-driven values differ.

Outer Boundary

Entry pkg/immutable/loader.go — LoadArtifacts() boot path

Test Surface Unit tests on the pre-render function + integration test via gateway/it/features/

Framework Go text/template, standard yaml.Unmarshal

Shell Boundaries

TypeComponentRole

Functional Core

Discovered via TDD. Expected shape:

  • BuildStructuralFuncMap() template.FuncMap — returns only structural functions (env, required, default, upper, lower, trim, replace). No secret, no redact.
  • PreRender(raw []byte, funcMap template.FuncMap) ([]byte, error) — executes template on raw bytes, returns rendered bytes.

Acceptance Criterion

Given an artifact YAML file with issuers: {{ env "ISSUERS" | required "ISSUERS must be set" }} (unquoted)

And the env var ISSUERS=[bit-ai-kc-ref, eiam-r]

When the gateway controller boots in immutable mode

Then the loaded config has issuers as a []interface{}{"bit-ai-kc-ref", "eiam-r"} (real array, not a string)

And scalar template fields (e.g. url: '{{ env "URL" }}') still resolve correctly

And {{ secret "X" }} in scalar fields still resolves with redaction tracking in pass 2

Test List

  1. Pre-render resolves {{ env "X" }} in raw bytes, producing valid YAML
  2. Pre-render with no {{ }} expressions returns bytes unchanged
  3. Pre-render with missing required env var returns error
  4. Pre-render does NOT resolve {{ secret "X" }} — function not in structural FuncMap (returns parse/execution error or is excluded)
  5. After pre-render + YAML parse, array-typed field contains real []interface{}
  6. Scalar fields with YAML-quoted templates ('{{ env "URL" }}') resolve to strings after pre-render + parse
  7. Pass 2 (RenderSpec) still resolves {{ secret "X" }} with tracker in scalar leaves
  8. Pass 2 skips already-resolved fields (no {{ remaining after pass 1)
  9. {{ env "KEY" | redact }} in YAML-quoted scalar — pass 1 resolves env, but redact not in structural FuncMap, so expression is left for pass 2 (OR: include redact as no-op passthrough in pass 1)
  10. Integration test: LlmProvider with templated issuers/audiences loads successfully and policy engine receives real arrays

Decision Context

Problem

Template expressions in array-typed fields fail because YAML parsing happens before template rendering. Templates can only produce strings, never arrays.

Chosen Approach

Two-pass rendering: pass 1 executes structural template functions on raw YAML bytes before parsing; pass 2 (existing RenderSpec) handles secret resolution and redaction tracking on parsed struct leaves.

Alternatives Considered

  • Custom fromJson/split function — rejected: even if the function produced a list, the rendered output is placed into a string field in map[string]any, never promoted to []any
  • Single-pass raw-bytes render with all functions — rejected: breaks secret/redact tracking (tracker lives in RenderSpec context); would require wiring tracker into a pre-parse context and handling double-render conflicts
  • Full-copy per environment — current workaround, doesn't scale (15 files vs 5)

Constraints

  • Separate FuncMaps enforce the pass-1/pass-2 split at compile time (contract-strength coupling)
  • Scoped to immutable loader only — management API doesn't need pre-render
  • Users must not YAML-quote array template expressions (same as Helm)

Open Questions

  • redact in pass 1 — should BuildStructuralFuncMap include redact as a no-op passthrough (so {{ env "X" | redact }} resolves in pass 1 without tracking), or exclude it (leaving the expression for pass 2)? Excluding it means YAML-quoted scalar fields with | redact still work via pass 2; including it as no-op means they resolve in pass 1 but lose redaction tracking. Recommendation: exclude redact from pass 1. Quoted scalars are preserved through YAML parse as strings, so pass 2 handles them correctly.

Uses

  • pkg/templateengine/funcs/registry.go — existing function registry (reuse env, required, default implementations)
  • pkg/templateengine/render.go — existing render() function (template parse + execute)
  • pkg/immutable/loader.go — insert point between os.ReadFile and parser.Parse
