Feature Request: Raw-YAML Artifact Templating

Enable Go text/template rendering on raw YAML bytes before parsing, so template expressions can produce non-scalar values (arrays, objects)

Problem

The Gateway Controller's artifact templating currently renders Go text/template expressions on individual string leaf values extracted from an already-parsed Go struct. The processing order is:

1. os.ReadFile(path)              → raw []byte
2. yaml.Unmarshal(data, &struct)  → typed Go struct (arrays become []string)
3. renderValue(leaf)              → template executes on each string field
4. json.Marshal → json.Unmarshal  → back into typed struct

Because YAML parsing happens before template rendering, template expressions can only produce scalar string values. A template expression in an array-typed field fails because the YAML parser needs to see a real list, and the rendered string [a, b, c] is treated as a JSON string (not a JSON array) during the final json.Unmarshal.

Concrete failing example

A LlmProvider definition with per-environment JWT issuers:

# This DOES NOT WORK today
apiVersion: gateway.api-platform.wso2.com/v1alpha1
kind: LlmProvider
metadata:
  name: ai-model-deepseek
spec:
  context: "/ai-model/deepseek/shared/v1"
  upstream:
    url: '{{ env "MODEL_BACKEND_URL" | required "MODEL_BACKEND_URL must be set" }}'    # ← works (scalar string field)
  policies:
    - name: jwt-auth
      version: v1
      paths:
        - path: "/*"
          params:
            issuers: '{{ env "ISSUERS" | required "ISSUERS must be set" }}'  # ← FAILS: issuers is []string
            audiences: '{{ env "AUDIENCES" | required "AUDIENCES must be set" }}'  # ← FAILS: audiences is []string
Why it fails: After YAML parse, the issuers field expects []string. The YAML value '{{ env "ISSUERS" | required "ISSUERS must be set" }}' is a scalar string, so yaml.Unmarshal into []string fails. Even if it were accepted as a single-element list, the rendered string [bit-ai-kc-ref, eiam-r] would remain a single string in the struct, not a list.

What works today

upstream:
  url: '{{ env "MODEL_BACKEND_URL" | default "http://localhost:8080" }}'  # ← scalar string, works
  auth:
    value: '{{ secret "API_KEY" | redact }}'  # ← scalar string, works (secret resolves + redact tracks)

Proposed Solution

Render Go text/template on the raw YAML bytes before parsing:

1. os.ReadFile(path)              → raw []byte
2. template.Execute(raw, funcMap) → rendered []byte    ← NEW: template runs on raw YAML
3. yaml.Unmarshal(rendered, &struct) → typed Go struct
4. (optional) leaf-level render for secret redaction tracking

This matches how Helm's tpl function works: template first, then YAML parse on the output. The rendered bytes must be valid YAML.

With this change, the example works

# Artifact YAML (no YAML quoting needed — template runs on raw text)
apiVersion: gateway.api-platform.wso2.com/v1alpha1
kind: LlmProvider
metadata:
  name: ai-model-deepseek
spec:
  context: "/ai-model/deepseek/shared/v1"
  upstream:
    url: {{ env "MODEL_BACKEND_URL" | required "MODEL_BACKEND_URL must be set" }}
  policies:
    - name: jwt-auth
      version: v1
      paths:
        - path: "/*"
          params:
            issuers: {{ env "ISSUERS" | required "ISSUERS must be set" }}
            audiences: {{ env "AUDIENCES" | required "AUDIENCES must be set" }}

With environment variables:

MODEL_BACKEND_URL=http://deepseek-predictor.bit-ai-models-r.svc.cluster.local:8080/v1
ISSUERS=[bit-ai-kc-ref, eiam-r, eiam-a]
AUDIENCES=[bit-ai-gateway, BIT-ai-assistant-dev, BIT-ai-assistant-test]

After template rendering (before YAML parse):

spec:
  upstream:
    url: http://deepseek-predictor.bit-ai-models-r.svc.cluster.local:8080/v1
  policies:
    - name: jwt-auth
      version: v1
      paths:
        - path: "/*"
          params:
            issuers: [bit-ai-kc-ref, eiam-r, eiam-a]       # ← valid YAML flow sequence
            audiences: [bit-ai-gateway, BIT-ai-assistant-dev, BIT-ai-assistant-test]

The YAML parser sees valid YAML with real arrays. No special quoting needed.

Impact

What this enables

  • Single API definition file shared across all environments — per-environment differences (URLs, issuers, audiences, credentials) all resolve from env vars at boot
  • Eliminates per-environment file copies for LlmProvider definitions that differ only in issuers/audiences/backend URL
  • Consistent with how Helm works — Helm renders templates on raw YAML, then parses. Same mental model for chart authors and API definition authors.

Without this feature (current state)

Each environment must carry a full copy of every LlmProvider YAML, differing only in 3 fields (upstream URL, issuers array, audiences array). For 5 models across 3 environments = 15 files, with ~90% duplication.

Backward compatibility

  • Existing artifacts with {{ env "VAR" }} in scalar fields still work — they produce valid YAML strings after rendering
  • Artifacts without any {{ }} expressions are unchanged — template rendering on inert text is a no-op
  • The redact function would need adaptation — the raw-YAML render pass doesn't have struct-level context for tracking which fields were redacted. A two-pass approach (raw-YAML render + leaf-level redact tracking) would preserve the existing config-dump redaction feature.
