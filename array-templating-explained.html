Why Array Templating Fails & How Pre-Render Fixes It

The core problem is ordering: YAML parse happens before template render, so templates can never produce non-string values.

The Current Pipeline (Today)

os.ReadFile(path)        → raw []byte         (template syntax still in text)
        ↓
yaml.Unmarshal(data)     → typed Go struct    (template syntax trapped in string fields)
        ↓
json.Marshal → map      → map[string]any    (generic tree, but types are locked in)
        ↓
renderValue(leaf)        → each string with {{ }} is executed through text/template
        ↓
json.Marshal → Unmarshal → back to typed struct (rendered values must fit the field type)

Walk through the failure

Consider this artifact YAML:

spec:
  policies:
    - name: jwt-auth
      params:
        issuers: '{{ env "ISSUERS" | required "ISSUERS must be set" }}'

With ISSUERS=[bit-ai-kc-ref, eiam-r] in the environment.

Step 1: YAML parse. The parser sees issuers: '{{ env "ISSUERS" ... }}'. The single-quotes make it a YAML scalar string. The params field is map[string]interface{}, so the parser stores:

params["issuers"] = "{{ env \"ISSUERS\" | required \"ISSUERS must be set\" }}" — a single Go string.
Step 2: Template render. renderValue finds this string contains {{, executes the template. env("ISSUERS") returns "[bit-ai-kc-ref, eiam-r]" (literally that text, including brackets). required checks it's non-empty, passes it through.

Result: params["issuers"] = "[bit-ai-kc-ref, eiam-r]" — still a single Go string.
Step 3: Re-marshal into typed struct. json.Marshal(map) produces "issuers": "[bit-ai-kc-ref, eiam-r]" (a JSON string, not a JSON array). When downstream code expects []string for issuers, it gets a single string element containing brackets. The policy engine receives garbage.

The fundamental constraint

Once YAML parsing runs, every value has a Go type. A string field stays a string no matter what the template produces. The template output is always placed back as a string in the map[string]any tree. There's no mechanism to "promote" a rendered string into an array after the fact.

Even with map[string]interface{} params: the YAML parser saw a quoted scalar, so it stored a string. The template engine renders string → string. The final json.Unmarshal sees "issuers": "[bit-ai-kc-ref, eiam-r]" which is a JSON string, not ["bit-ai-kc-ref", "eiam-r"] which would be a JSON array.

The Proposed Solution: Pre-Render on Raw Bytes

os.ReadFile(path)            → raw []byte       (template syntax in text)
        ↓
template.Execute(raw)        → rendered []byte  ← NEW: template runs on raw YAML text
        ↓
yaml.Unmarshal(rendered)     → typed Go struct  (parser sees valid YAML with real arrays)
        ↓
renderValue(leaf)            → second pass for secret/redact tracking only
        ↓
json.Marshal → Unmarshal    → typed struct (everything fits)

Walk through the fix

Same artifact, but without YAML quoting (since the template runs on raw text):

spec:
  policies:
    - name: jwt-auth
      params:
        issuers: {{ env "ISSUERS" | required "ISSUERS must be set" }}

With ISSUERS=[bit-ai-kc-ref, eiam-r] in the environment.

Step 1: Template execute on raw bytes. Go's text/template sees the {{ }}, calls env("ISSUERS") which returns [bit-ai-kc-ref, eiam-r]. The template output replaces the expression in the raw text.

The raw bytes now read: 
spec:
  policies:
    - name: jwt-auth
      params:
        issuers: [bit-ai-kc-ref, eiam-r]
This is valid YAML — a flow sequence.
Step 2: YAML parse. The parser sees issuers: [bit-ai-kc-ref, eiam-r] and correctly produces:

params["issuers"] = []interface{}{"bit-ai-kc-ref", "eiam-r"} — a real Go slice.
Step 3: Everything downstream works. The typed struct gets a proper []string. Policy engine receives a real array. No garbage.

Why This Works (the Key Insight)

The template output becomes part of the YAML syntax itself. When the env var value is [bit-ai-kc-ref, eiam-r], the rendered text contains a YAML flow sequence. The YAML parser then interprets it as structure, not as a string.

Post-parse render (today)

Template input:  a Go string
Template output: a Go string
Context: string → string
Cannot change type.

Pre-parse render (proposed)

Template input:  raw text bytes
Template output: raw text bytes
Context: text → YAML parser
Can produce any YAML structure.

The Redaction Complication

The existing secret and redact template functions track sensitive values via SecretTracker during rendering. If we only do pre-render, we'd need the tracker wired into the pre-render pass. But there's a clean two-pass solution:

PassWhat runsPurpose
1 (pre-parse)env, required, default, upper, lower, trim, replaceStructural: produces valid YAML (arrays, objects)
2 (post-parse, existing)secret, redact + all othersSecret resolution + tracking for config-dump redaction

Pass 1 handles the structural problem (arrays). Pass 2 handles secrets with tracking intact. Existing scalar templates ({{ env "URL" }}) work in both passes — they're idempotent on already-resolved values since they won't contain {{ anymore after pass 1.

Backward compatible: artifacts that only use templates in scalar string fields still work. Pass 1 resolves them to plain strings, YAML parses the string, pass 2 finds no remaining {{ and skips them.

Corrected Template Syntax

The feature request incorrectly shows {{ required "ISSUERS" }}. The actual required function takes (msg, val string) for pipe compatibility. Correct syntax:

Wrong (feature request)

issuers: {{ required "ISSUERS" }}
audiences: {{ required "AUDIENCES" }}

required expects 2 args: error message + value

Correct

issuers: {{ env "ISSUERS" | required "ISSUERS must be set" }}
audiences: {{ env "AUDIENCES" | required "AUDIENCES must be set" }}

env fetches, pipes into required which validates non-empty
